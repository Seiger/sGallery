# Фоновая оптимизация изображений

## Быстрые и медленные преобразования

sGallery обрабатывает изображения без кеша синхронно, если хватает памяти
веб-запроса. Типовой
кооперативный бюджет — пять секунд; его задаёт пакет, значение доступно через
`Seiger\sGallery\sGallery::optimizationBudgetSeconds()`. Готовый непустой кеш
возвращается сразу; пустые файлы генерируются заново.

Автоматический подбор качества WebP сохраняет 15 кандидатов:
`99, 97, 95, 93, 92, 91, 90, 89, 88, 87, 86, 85, 84, 82, 80`.
Выбирается первый кандидат, укладывающийся в целевой размер, либо последний,
если ни один не подошёл. Явный `quality()` использует одно заданное значение.
Нативный путь поддерживает явное качество WebP 100. Качество по умолчанию
из конфигурации и путь со Spatie используют верхнюю границу 99.
Только завершённый непустой WebP атомарно публикуется из временного файла.

Бюджет проверяется между преобразованиями и попытками кодирования. Он не может
прервать уже работающий native encoder: первая обработка может превысить пять
секунд или действующий PHP timeout. Отметка медленного преобразования хранится
в общем storage, и следующие запросы пропускают синхронную обработку.
Незавершённые временные файлы не выдаются как готовые изображения.

## Необязательная интеграция sTask

sTask выполняет поддерживаемые нативные преобразования через GD или Imagick без
Spatie. Для анимированных GIF и WebP нужен Imagick. При наличии Spatie воркер
использует обработку через Spatie.

Пакет устанавливается независимо. Для передачи в очередь нужны установленные
runtime-классы sTask, API `heartbeat()` и актуальный heartbeat runner-а.
Старые версии sTask без этого API не получают отложенные задания.

Воркер — `Seiger\sGallery\Workers\ImageOptimizationWorker`, идентификатор —
`sgallery.image-optimization`, действие — `optimize`. Первое отложенное задание
регистрирует отсутствующий воркер активным. Существующий отключённый воркер
не включается автоматически: разрешите выполнение в менеджере sTask.

После исчерпания бюджета фронт возвращает URL оригинала. Если sTask недоступен,
heartbeat просрочен или постановка в очередь не удалась, оригинал остаётся
доступным, а дорогое преобразование не повторяется в каждом запросе. Уже открытое
изображение не заменяется автоматически. После успешного задания воркер очищает
кеш страниц и Blade views Evolution, чтобы последующие запросы использовали
готовое изображение. Кеш производных изображений не очищается.

## Большие изображения

sGallery оценивает память для оригинала, производного и промежуточных
изображений до декодирования. Фиксированного ограничения в пикселях нет.
Веб-запрос использует до половины свободной памяти PHP после резерва 16 МиБ
для приложения. При `memory_limit=-1` начальный бюджет оценки составляет
128 МиБ. Если преобразование выходит за пределы этого запаса, sGallery
передаёт его в sTask и возвращает URL оригинала. Оригинал доступен и когда
очередь не принимает задание. Готовые производные выдаются из кеша.

## Идентичность задания и восстановление

Задание сохраняет путь источника, его размер, время изменения и SHA-256 содержимого, выбранный формат,
параметры преобразования и настройки явного качества. Удалённые источники не
попадают в очередь. Изменение источника во время ожидания отклоняет старое задание.
Неблокирующий lock для задания и дедупликация sTask предотвращают дубликаты.
После ошибочного или завершённого задания без пригодного кеша повторная
постановка имеет паузу пять минут; активные задания используются повторно.
Сохранённые скалярные параметры геометрии работают в обоих путях обработки.
После нормализации метаданных sTask воркер восстанавливает порядок параметров
watermark, чтобы готовый файл имел тот же ключ кеша, что и следующий запрос frontend.
Изменение содержимого водяного знака проверяется перед публикацией.

Ключ производного файла содержит полный путь и версию источника: замена
с прежними размером и mtime не возвращает старые пиксели. Отпечаток вычисляется
потоковым чтением, в том числе при попадании в кеш. Воркер сверяет версию до
и после финальной публикации и перед успешным завершением. При обнаружении
замены возле публикации только что записанный устаревший кандидат удаляется;
актуальная версия имеет другой ключ. Источник и прежние исправные производные
файлы сохраняются. Старые задания size/mtime принимаются при совпадении этих
полей, затем фиксируют текущий отпечаток. Они не обнаруживают замену с прежними
статистическими данными до выполнения, но обрабатывают текущие байты под текущим ключом.

Служебные файлы находятся в `storage/sgallery/optimization`. Storage должен
быть общим между релизами и доступным для записи фронтовому и CLI пользователям.

## Выполнение заданий в sTask

Штатный runner sTask вызывает воркер sGallery в своём PHP-процессе. Воркеру
нужен доступ на запись в кеш изображений. Перед обработкой он повторно сверяет
оценку памяти с `memory_limit` runner-а. При значении `-1` начальный бюджет
оценки составляет 512 МиБ.

После проверки готовое изображение публикуется атомарным переименованием файла.
sTask фиксирует обрабатываемые ошибки и переходит к следующему заданию.
Фатальная ошибка, завершающая PHP-процесс runner-а, может прервать текущий запуск.
Кеш страниц очищается после успешного задания.

## Проверка

Запустите интеграционные тесты с Composer runtime установленного Evolution,
sTask с heartbeat API, поддержкой GD/WebP и SQLite:

```sh
SGALLERY_AUTOLOAD=/path/to/site/core/vendor/autoload.php php tests/image-optimization.php
php tests/optional-stask.php
```
